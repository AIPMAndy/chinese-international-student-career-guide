# 投递、跟进与卡点诊断

申请台账的目的，是知道哪里还在推进、下一步该做什么。它不是用来制造漂亮转化率。

## 一条申请的完整记录

至少记录：地区、雇主、职位编号、招聘原文、招聘类别、毕业范围、工作资格、担保说明、截止日与时区、简历版本、申请日、回执、各阶段实际发生日期、当前状态、下一动作、下一动作日期、结束原因。

同一职位从官网、校友和平台看到三次，只记一条岗位。发现渠道可以多条，正式提交不要重复，除非雇主允许重新申请。

## 投递操作五步

**准备什么：** 资格检查表、定向材料、真实的毕业与身份信息、可正常收信的邮箱。

**具体怎么做：** 进入核验过的招聘入口，核对职位编号，逐项填写，再检查系统解析。评估题按规则由本人完成。提交后保存回执与材料版本，标记下一次检查日期。

**得到什么：** 一次有凭证的申请，而不是仅收藏职位或上传到个人简历库。

**如何验收：** 系统显示已提交，或收到明确回执；台账能追溯提交内容与日期；没有把自动邮件计为人工回复。

**卡住怎么办：** 上传失败先查大小、格式和文件名要求；系统无法选择学校时按官方指引填准确全称并询问支持；临近截止要保存错误信息并通过官方渠道反馈，不能假定反馈等于延长截止。

## 跟进的节奏

先遵守雇主明确的时间表和“请勿重复联系”要求。没有明确安排、且存在合适联系渠道时，可以在合理等待后礼貌询问一次。个人可以先设一周左右的检查提醒，但这不是雇主承诺的处理时限。

跟进邮件写职位编号、申请日期、仍有兴趣和可补充材料。不要以焦虑为理由每天催问。明确拒绝后停止催促；若有未来申请规则，记录下一次允许申请的时间。

## 用观察到的事件复盘

| 观察到的卡点 | 先排查 | 下一项验证动作 |
|---|---|---|
| 没有人工回复 | 岗位是否仍有效、资格和毕业范围、材料与岗位、联络方式 | 逐条复核最近一批已提交记录 |
| 有回复，不能约面 | 到岗日、时区、资格、薪资与地点是否冲突 | 写清条件，请招聘方确认最关键的一项 |
| 面试后停滞 | 真实评估反馈、证据不足、表达或岗位变化 | 复盘原题和回答，做一次定向模拟 |
| 多次流程结束 | 是否集中在同一国家、项目或门槛 | 分组看共同条件，避免全盘否定自己 |
| 有Offer但不合适 | 资格有效期、用工主体、到岗与现金条件 | 形成书面问题表并比较可行选项 |

这些是排查假设，不是对拒绝原因的确定判断。没有回复不等于简历差，也不能据此推断某群体被统一拒绝。

## 周复盘只改一个主要变量

先选同一时间段、同一岗位类别的申请作为观察组，保留尚未到雇主反馈期的岗位。统计真实发生的人工回复、面试完成、后续推进与书面 Offer，给出分母和日期。不要用最高阶段反推每一阶段一定发生。

下周选择一个可观察改动，例如把最相关证据移到前面，或调整目标岗位范围。小样本只用于发现问题，不宣布“这个方法提升了多少成功率”。
